# デプロイ手順

しごとみっけを、自分のアカウントの無料プランで本番公開するときの手順と順番。
この手順だけで、同じ環境を作り直せることを目的にする。

> キー・パスワード・接続文字列などの値は、この文書に書かない。各サービスの画面からコピーして、Render・Vercel の画面に直接入れる。

---

## 1. 全体の構成

```
ブラウザ（生徒・先生）
  │
  ├─ フロント：Vercel（Next.js）  https://shigoto-mikke.vercel.app
  │     └─ Firebase Authentication（管理者ログイン）
  │
  └─ API：Render（Docker・Express）  https://shigoto-mikke.onrender.com
        ├─ DB：Neon（PostgreSQL）
        ├─ キャッシュ・回数制限：Upstash（Redis）
        ├─ 管理者のトークン検証：Firebase Admin SDK
        ├─ AI：OpenRouter（openai/gpt-oss-120b）
        └─ 決済：Stripe（テストモード）→ Webhook で契約を更新
```

| サービス | 用途 | プラン | リージョン |
|---|---|---|---|
| Neon | PostgreSQL | Free | Singapore |
| Upstash | Redis | Free | Singapore |
| Firebase | 管理者ログイン | Spark（無料） | — |
| OpenRouter | AI の説明文 | 前払い（少額） | — |
| Stripe | 決済 | テストモード | — |
| Render | API | Free | Singapore |
| Vercel | フロント | Hobby | — |

## 2. 順番

URL が決まらないと設定できない値があるため、次の順で進める。

1. 外部サービスを用意する（§3）
2. Render で API を公開する（§4）。`FRONTEND_URL` は仮の値にしておく
3. 本番 DB に seed を流す（§5）
4. Vercel でフロントを公開する（§6）
5. URL が決まったので、つなぎ直す（§7）
6. 通しで確認する（§8）

---

## 3. 外部サービスの準備

### Neon（PostgreSQL）
- プロジェクトを作る（リージョン：Singapore）
- Connection pooling は **オフ** の接続文字列を使う（`prisma migrate deploy` のため）
- → `DATABASE_URL`

### Upstash（Redis）
- データベースを作る（リージョン：Singapore）
- TCP の接続文字列（`rediss://` で始まる TLS のもの）を使う。前後の `REDIS_URL="` と `"` は除く
- → `REDIS_URL`

### Firebase
- **自分のプロジェクトを開いているか、左上のプロジェクト名を毎回確認する**（チームのプロジェクトと名前が似ているため）
- Authentication で「メール/パスワード」を有効にする
- 管理者ユーザーを1人作り、UID を控える → `SEED_FIREBASE_UID_TRIAL`
- ウェブアプリを登録する（Hosting は不要）→ `NEXT_PUBLIC_FIREBASE_API_KEY`・`_AUTH_DOMAIN`・`_PROJECT_ID`
- プロジェクトの設定 → サービスアカウント → 新しい秘密鍵を生成（JSON）→ `FIREBASE_PROJECT_ID`・`FIREBASE_CLIENT_EMAIL`・`FIREBASE_PRIVATE_KEY`
  - JSON ファイルはリポジトリのフォルダに置かない

### OpenRouter
- 少額をチャージする（自動チャージは使わない）
- API キーを作る。Credit limit を設定する（例：$2、Monthly でリセット）
- モデルはコードで固定しているので、選ぶ必要はない
- → `OPENROUTER_API_KEY`

### Stripe（テストモード）
- 商品「年額プラン」と価格（50,000 円・JPY・一括）を作る → `STRIPE_PRICE_ID`
- 開発者 → API キーのシークレットキー → `STRIPE_SECRET_KEY`
- Webhook は URL が決まってから作る（§7）

### SESSION_SECRET
- 自分のターミナルで作る（値は会話やファイルに残さない）
  ```bash
  openssl rand -hex 32
  ```

## 4. Render（API）

New → Web Service → GitHub のリポジトリを選ぶ（GitHub 連携は「Only select repositories」でこのリポジトリだけ許可する）。

| 項目 | 値 |
|---|---|
| Language | Docker |
| Branch | `main` |
| Region | Singapore |
| Root Directory | `backend` |
| Dockerfile Path | `backend/Dockerfile.prod` |
| Docker Build Context Directory | `backend/ .`（そのまま） |
| Health Check Path | `/v1/health` |
| Docker Command | 空欄（Dockerfile の CMD で、マイグレーション → 起動 を行う） |
| Instance Type | Free |

### 環境変数

| キー | 値の取り方 |
|---|---|
| `DATABASE_URL` | Neon |
| `REDIS_URL` | Upstash |
| `SESSION_SECRET` | §3 で作った値 |
| `FIREBASE_PROJECT_ID` | 自分の Firebase のプロジェクト ID |
| `FIREBASE_CLIENT_EMAIL` | サービスアカウントの JSON の `client_email` |
| `FIREBASE_PRIVATE_KEY` | JSON の `private_key`。`\n` が入った1行のまま貼る（前後の `"` は入れない） |
| `OPENROUTER_API_KEY` | OpenRouter |
| `STRIPE_SECRET_KEY` | Stripe |
| `STRIPE_PRICE_ID` | Stripe |
| `FRONTEND_URL` | 最初は仮で `http://localhost:3000`。§7 で Vercel の URL に変える |
| `STRIPE_WEBHOOK_SECRET` | §7 で追加する |
| `SEED_FIREBASE_UID_TRIAL` | §5 で追加する |

- `PORT` と `NODE_ENV` は入れない（Render と Dockerfile が設定する）
- 「Add from .env」は使わない（ローカル用の値が入るため）
- **Secret Files ではなく、Environment Variables に入れる**（アプリは環境変数から読む）

### 確認
- ログに `2 migrations found` と `All migrations have been successfully applied`（2回目以降は `No pending migrations to apply.`）が出る
- `https://<サービス名>.onrender.com/v1/health` が `{"status":"ok"}` を返す

## 5. seed（マスタとデモ校）

無料プランでは Render の Shell が使えないため、起動コマンドを一時的に変えて1回だけ流す。

1. Environment に `SEED_FIREBASE_UID_TRIAL`（§3 で控えた UID）を追加する
2. Settings → Docker Command に次の1行を入れて保存する（デプロイが始まる）
   ```
   pnpm exec prisma db seed
   ```
3. ログに `[seed] 完了` と `The seed command has been executed.` が出るのを確認する
   - seed が終わるとアプリが終了するため、このデプロイは「Deploy failed」になる。前の正常なバージョンが動き続けるので問題ない
4. **すぐに Docker Command を空欄に戻して保存する**（戻さないと、起動のたびに seed が流れる）
5. 新しいデプロイが Live になるのを確認する

入るもの：好きなこと12・特性5・質問5・職業39・デモ校4（`UEDA123` は無料体験中）。

- Docker Command では `&&` が使えない（`sh -c "..."` も不可）。1つのコマンドだけを入れる
- 2回目以降に流すときは、`SEED_DEMO_SCHOOLS=false` を環境変数に足してから流す（契約の状態を上書きしないため）

## 6. Vercel（フロント）

Add New → Project → リポジトリを Import する（GitHub 連携は「Only select repositories」）。

| 項目 | 値 |
|---|---|
| Root Directory | `frontend` |
| Application Preset | Next.js |
| Build and Output Settings | すべて自動（スイッチはオフのまま） |
| Production Branch | `main`（Settings → Environments → Production） |

### 環境変数

| キー | 値 | Type |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | Render の URL（最後の `/` は付けない） | どちらでも可 |
| `NEXT_PUBLIC_FIREBASE_API_KEY` | 自分の Firebase のウェブアプリの `apiKey` | Config |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | `<プロジェクトID>.firebaseapp.com` | Config |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | 自分の Firebase のプロジェクト ID | Config |

- `NEXT_PUBLIC_` の値はブラウザに見える。秘密の値は入れない（秘密の値は Render だけに入れる）
- `NEXT_PUBLIC_` の付いた変数は Secret にできない。Config で作る（Secret で保存したものは Config に変えられないため、削除して作り直す）
- 値を変えたら **Redeploy** する（`NEXT_PUBLIC_*` はビルド時に埋め込まれる）。Deployments → 一番上の「…」→ Redeploy。Build Cache は使わない

### 確認
- 本番の URL で入口画面と画像が表示される
- この時点では、API への通信は CORS で止まる（§7 で直る）

---

## 7. つなぎ直し

1. Render の `FRONTEND_URL` を Vercel の本番 URL にする（最後の `/` は付けない）→ Save, rebuild, and deploy
   - CORS で許可するのは、この URL だけ。Vercel のプレビュー用 URL からは API を呼べない
2. Firebase → Authentication → 設定 → 承認済みドメイン に、Vercel の本番ドメインを足す（`https://` は付けない）
3. Stripe（テストモード）→ Webhook → 送信先を追加
   - スコープ：お客様のアカウント／ペイロード：スナップショット
   - イベント：`checkout.session.completed` だけ
   - 送信先：Webhook エンドポイント `https://<API>/v1/billing/webhook`
4. 送信先の署名シークレット（`whsec_…`）を、Render の `STRIPE_WEBHOOK_SECRET` に入れる → Save, rebuild, and deploy

## 9. つまずいたこと

| 起きたこと | 原因 | 直し方 |
|---|---|---|
| 管理者ログインで「メールアドレスまたはパスワードを確認してください」 | Vercel の Firebase の値が、チームのプロジェクトのものだった | 自分のプロジェクトの値に直して Redeploy |
| seed のときに `not found` や、seed が流れない | Docker Command で `sh -c` や `&&` を使った | `pnpm exec prisma db seed` だけを入れる |
| Vercel で `NEXT_PUBLIC_` の変数を Edit できない | Secret の変数に公開用の接頭辞が付いている | 削除して Config で作り直す |
| Webhook の値を入れたのに読まれない | Render の Secret Files に入れていた | Environment Variables に入れる |
| Vercel で「Project already exists」 | 1回目の画面で、プロジェクトだけ作られていた | 既存のプロジェクトの設定を直して使う |

## 10. 運用メモ

- Render の無料プランは、15分アクセスがないと止まり、次のアクセスで起動に約1分かかる
- ログに出る Prisma の「Update available」は無視してよい（メジャー更新は別作業）
- Stripe はチーム開発のときと同じアカウントのテストモードを使っている。テスト支払いの通知は、チームの Webhook にも届く（チームのデータには影響しない）
- デモ校 `UEDA123` は、テスト支払いで契約中にしてある（有効期限：2027-11-03）
